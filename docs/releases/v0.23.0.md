# v0.23.0 Sales Order Lifecycle

Release date: 2026-08-14

## Scope

- Added a seller-facing sales-order queue for pending shipment, authentication, settlement, return, refund, and cancellation.
- Made sales-order creation the default outbound workflow. Creation reserves inventory, while shipment writes the outbound ledger exactly once without deducting inventory again.
- Preserved the existing direct-ledger mode for already completed transactions and historical bookkeeping.
- Added optional platform order number and seller note fields to account-isolated outbound drafts.
- Added paginated order queues and a paginated per-order event timeline. Uncertain action responses are reconciled against the latest database state before the seller is asked to retry.
- Connected authenticated order settlement to the existing audited outbound-settlement flow. Corrections keep their own settlement audit without duplicating the order transition.
- Upgraded the complete ledger package to schema `dewu-seller-pro/ledger-backup@5`, including orders and order events without replaying inventory reservation during restore. Packages `@1` through `@4` remain preview-compatible.
- Added server-side restore limits and validation for event states, per-record size, estimated values, and already-linked outbound activities.

## Accounting guarantees

- Order creation, shipment, cancellation, return, and settlement use transactional `SECURITY DEFINER` RPC/trigger paths with authenticated ownership checks.
- Operation IDs bind request fingerprints. Replays return the stored result, and stale status/version requests are rejected.
- Authentication failure does not restore inventory. Physical inventory is restored only by cancellation before shipment or confirmed return, at most once.
- Client roles retain read-only access to order and event tables; direct writes remain revoked.
- Complete backup restore records history only and does not replay inventory changes.

## Boundaries

- This remains an Android closed-test product. The hosted site remains a policy, support, and authentication-callback surface rather than an inventory application.
- Public self-service registration and password email delivery still require a user-owned domain and custom SMTP before public launch.
- Order-detail timeline behavior is covered by mapping/UI tests and remote temporary-account API smoke; the retained real-account screenshots intentionally stop before any write.
- The next product milestone can build the AI Agent on these stable order tools instead of allowing the model to invent order state transitions.
