# v0.20.2 stale chunk recovery

- Detects stale hashed dynamic-import chunks after a web deployment and performs one automatic full-page refresh per loaded entry version.
- Uses a session-scoped entry fingerprint to prevent refresh loops. A repeated stale-chunk failure shows an explicit `刷新应用` action instead of retrying the same obsolete URL.
- Keeps offline and ordinary network failures on the local retry path; offline failures never trigger an automatic full reload.
- Handles both Vite `vite:preloadError` events and React deferred-import rejections, including browser-specific wrapped errors.
- Starts the deferred product-image cleanup queue only once per signed-in account session to avoid duplicate requests and warnings.

## Verification

- A production-preview browser regression removed the active `Profile` hash chunk after page load: the first click refreshed to Home, the second stopped at the explicit refresh prompt, and restoring the chunk made Profile load normally.
- The disposable test account was deleted through the app account-deletion flow; no real inventory or financial records were written.

Public launch remains blocked on a user-owned domain and custom SMTP. Production remains a closed test with email auto-confirm enabled.
