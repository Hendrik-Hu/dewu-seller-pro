# v0.20.3 public-launch governance gate

This is a repository-governance release. The shipped web and Android application runtime remains v0.20.2, so no production deployment or Android re-signing is required.

## Added

- `npm run check:public-launch` is the single repeatable public-release gate.
- The gate rejects hosting-default domains, verifies non-secret Supabase Auth mail state, requires recent registration-confirmation and password-recovery evidence, checks public routes and security headers, and binds Android App Links to the current package and public signing-certificate fingerprint.
- Every failed gate exits non-zero with Chinese blocker text and writes a non-sensitive JSON report.
- Behavioral tests cover the fully passing state, the expected closed-test state, missing security headers, stale mail evidence, App Link mismatch, and sensitive-value exclusion.

## Closed-test result

The current production environment correctly fails with exactly two top-level blockers:

1. A user-owned HTTPS domain is not configured; the current `vercel.app` hostname is a hosting default.
2. Custom SMTP and recent real registration-confirmation/password-recovery mail evidence are not complete.

The production home, privacy statement, account-deletion statement, public support endpoint, required security headers, and Android `assetlinks.json` package/certificate binding pass. No SMTP password, management token, test email address, mail link, or message content is stored in the report.
